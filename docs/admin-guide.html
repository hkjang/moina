MOINA 관리자 가이드

외부 PostgreSQL 준비와 오프라인 이미지 반입부터 Keycloak, AI, 역할·권한, 선택형 승인과 신고·감사 운영까지 실무 순서로 정리했습니다.

버전 v0.1.1linux/amd64외부 PostgreSQLdistroless non-root

목차

배포 전 점검오프라인 설치최초 로그인일반 설정Keycloak OIDC역할·권한·키AI 설정승인 정책신고·제재백업·업그레이드사설 CA관측·이벤트 복구실제 화면장애 대응

3. 최초 관리자 로그인

  1. reverse proxy의 HTTPS 주소로 접속해 로그인 화면 버전을 확인합니다.
  2. bootstrap 아이디와 비밀번호로 로그인합니다.
  3. 개인 설정에서 bootstrap 비밀번호를 즉시 변경합니다.
  4. 별도 운영 관리자와 검토 역할을 만들고 최소 권한을 부여합니다.
  5. audit log에 최초 로그인, 비밀번호 변경과 사용자 생성 기록이 남았는지 확인합니다.

bootstrap 정보는 최초 계정을 보장하기 위한 값입니다. 이미 계정이 생성된 뒤 환경변수 비밀번호를 바꿔 기존 계정을 덮어쓰지 않습니다.

4. 일반 설정

서비스 관리자 → 일반 설정에서 서비스 이름, 기본 시간대, session 유지 시간, 사용자 가입, 개인 API key·MCP와 key별 요청 한도를 관리합니다. 미디어 설정에서는 파일 크기, Moin당 첨부 수와 미사용 업로드 TTL(1~720시간, 기본 24시간)을 관리합니다. 환경변수는 추가하지 않습니다.

  • 새 미디어는 PostgreSQL Large Object로 streaming하며 기존 bytea 미디어를 계속 읽습니다.
  • 사용자별 미첨부 media 100개·512 MiB quota는 고정 한도입니다. 초과 시 media_quota_exceeded가 표시되며 기존 업로드를 Moin·프로필에 연결하거나 TTL 정리를 기다립니다.
  • Large Object read는 인스턴스당 최대 8개이고 작은 DB pool에서는 일반 API 연결 5개를 남기도록 더 줄입니다.
  • TTL이 지난 미사용 업로드는 내장 worker가 매시간 500개씩 최대 20 batch, 인스턴스당 최대 10,000개를 SKIP LOCKED로 삭제합니다.
  • 작성 화면은 GET /api/v1/media/config에서 현재 최대 byte, Moin당 개수와 허용 MIME을 읽습니다. 관리자 전용 orphan TTL과 고정 quota는 이 응답에 포함되지 않습니다.
  • OIDC redirect URL은 Keycloak/OIDC 전용 설정에서 입력하거나 현재 요청 주소를 기준으로 자동 생성합니다.
  • 설정 변경과 수행자는 audit log에 기록하되 비밀값 원문은 남기지 않습니다.
  • 개인화 화면과 관리자 화면은 메뉴 그룹과 권한 경계를 분리합니다.
public base URL, 동시 session 수, Moin 길이, WebSocket·검색 정책과 media 고정 quota는 v0.1.1 관리자 설정 항목이 아닙니다.

5. Keycloak OIDC

  1. Keycloak에 confidential client를 만들고 Authorization Code flow와 PKCE를 허용합니다.
  2. 관리 화면에 issuer URL, client ID, client secret과 redirect URL을 입력합니다.
  3. 허용 호스트에 issuer와 discovery가 사용할 정확한 DNS 이름 또는 host:port를 등록합니다. port 없는 항목은 URL scheme 기본 port에만 일치합니다.
  4. DNS가 RFC1918/ULA 사설 주소를 반환하면 같은 정확한 DNS hostname을 사설망 허용 호스트에도 등록합니다. 두 목록의 authority와 비기본 port가 일치해야 합니다.
  5. scope는 openid profile email부터 시작하고 기본 역할, claim mapping과 자동 사용자 생성을 설정합니다.
  6. 연결 테스트에서 discovery, token endpoint, DNS/IP, redirect와 TLS를 확인한 뒤 활성화합니다.

Wildcard, scheme, 경로와 사용자 정보는 허용 목록에 입력하지 않습니다. 사설망 허용 목록에는 IP literal을 넣지 않으며 loopback·link-local·cloud metadata·CGNAT·unspecified·multicast는 항상 차단됩니다. 최초 요청과 discovery endpoint, 모든 redirect는 허용 목록을 다시 검사합니다. 폐쇄망 HTTP는 allowInsecureHttp를 명시적으로 켠 등록 host에만 허용합니다. client secret은 저장 후 다시 노출하지 않으며 설정 여부만 표시합니다.

v0.1.0 업그레이드 필수: 기존 사설 OIDC·AI host는 자동으로 privateAllowedHosts에 들어가지 않습니다. 업그레이드 전 로컬 bootstrap 최고 관리자 로그인을 검증하고, 업그레이드 뒤 그 계정으로 각 정확한 hostname을 전체·사설망 허용 목록에 저장한 다음 연결 테스트를 실행하세요. 환경변수 비밀번호 변경은 이미 생성된 bootstrap 계정을 재설정하지 않습니다.
긴급 접근을 위해 최소 한 명의 로컬 최고 관리자 계정을 유지하고 강한 비밀번호와 접근 통제를 적용하세요.

6. 역할, 권한과 키

역할 이름과 permission 묶음은 관리자 화면에서 변경할 수 있습니다. 서버는 화면 숨김이 아니라 모든 API 요청에서 권한을 다시 검사합니다.

원칙적용
최소 권한읽기, 작성, moderation, 사용자, 설정과 audit를 분리하고, 실패 이벤트 조회 audit:read와 재처리 outbox:manage를 별도로 부여
개인 키소유자별 hash 저장, 원문 1회 표시, 만료와 최근 사용 기록
회전새 token 발급과 동시에 이전 token 무효화
MCP동일 permission 체계와 rate limit 적용, 관리 작업은 session 또는 별도 정책

역할 변경은 활성 session과 키의 유효 권한에 즉시 반영되어야 합니다. 정기적으로 장기 미사용 키와 만료 없는 키를 검토하세요.

7. AI 스트리밍 설정

내부 OpenAI-compatible endpoint의 base URL, API key, model, API style, timeout, token 정책과 허용 호스트를 저장합니다. API key는 encryption key로 암호화하고 응답에 반환하지 않습니다.

  • streaming은 기본값이며 SSE 연결을 reverse proxy가 buffering하지 않도록 합니다.
  • output token 허용 범위는 1~262,144이지만 실제 model 상한 이하로 설정합니다.
  • 허용 호스트에는 정확한 DNS/IP 또는 필요한 host:port만 등록합니다. port 없는 값은 HTTP 80 또는 HTTPS 443에만 일치합니다.
  • RFC1918/ULA로 해석되는 내부 endpoint는 정확한 DNS hostname을 전체 허용과 사설망 허용 목록에 함께 등록합니다. 항상 차단되는 주소 범주는 OIDC와 같습니다.
  • URL은 HTTPS가 기본이며 폐쇄망 HTTP는 allowInsecureHttp와 등록 host가 모두 일치할 때만 허용됩니다.
  • 요청마다 DNS를 다시 해석해 검증한 IP로 연결하고 모든 redirect를 다시 확인합니다.

연결 테스트는 저장된 설정으로 /models 응답을 확인합니다. host allowlist와 별개로 outbound 방화벽도 같은 목적지만 허용하세요. 사용자 입력과 응답 보존은 upstream gateway의 조직 정책도 함께 점검합니다.

8. 선택형 검토·승인 정책

승인 정책이 꺼져 있으면 제출·검토·승인·반려 단계와 승인 메뉴를 제외합니다. 켜면 지정 action에만 적용합니다.

  1. 정책을 켜고 검토 대상 action과 approver 역할을 선택합니다.
  2. 요청자가 Moin을 제출하면 암호화된 승인 snapshot을 저장하고 게시 전 대기 상태로 둡니다.
  3. 자기 승인을 금지하고 검토자가 승인하거나 사유를 포함해 반려합니다.
  4. 승인 대기 중인 Moin은 수정할 수 없으며, 내용을 바꾸려면 새 요청을 제출합니다.

승인·반려 event에는 actor, 시각, 대상, 결과와 검토 comment가 감사 log에 기록됩니다.

9. 신고와 제재 운영

v0.1.1 관리자 화면은 접수된 신고의 검토·해결·기각, 사용자 활성 상태와 게시물 삭제를 제공합니다. 신고 유형, 우선순위, SLA와 보존 기간을 사용자 정의하는 설정은 제공하지 않습니다.

  • 검토 메모에는 판단 근거를 남기고 필요한 moderation 권한만 부여합니다.
  • 사용자 비활성화와 게시물 삭제는 영향 범위를 확인한 뒤 수행합니다.
  • 기관별 보존 기간과 escalation 기준은 별도 운영 정책으로 관리합니다.
  • 반복 패턴을 관찰하되 자동 판단만으로 영구 제재하지 않습니다.

10. 백업과 업그레이드

백업

Large Object를 포함한 PostgreSQL 전체 backup, 동일한 encryption key와 현재 image tar.gz를 서로 다른 보안 영역에 보관합니다. 논리 backup은 사용 중인 PostgreSQL의 blob 포함 옵션(pg_dump -b 등)을 명시합니다. v0.1.1은 online root-key rotation을 제공하지 않으므로 복구 훈련에서 미디어, DB backup과 원래 key가 함께 유효한지 확인합니다.

업그레이드

  1. release notes와 migration을 검토하고 DB backup을 만듭니다.
  2. 서비스 중단 전에 로컬 bootstrap 최고 관리자 로그인을 확인합니다.
  3. 새 tar.gz의 SHA256을 확인하고 이미지를 load합니다.
  4. staging에서 최대 30분 migration 시간, 로그인, Flow·검색·알림과 rollback을 검증합니다.
  5. compose image tag를 바꾸고 재시작한 뒤 readyz, 버전과 metrics를 확인합니다.
  6. v0.1.0의 사설 OIDC·AI endpoint는 로컬 관리자로 privateAllowedHosts를 명시 저장·테스트합니다.

적용된 migration의 SHA-256 checksum이 달라지면 서버가 시작을 중단합니다. DB에 현재 binary가 모르는 migration version이 있어도 downgrade guard가 기동을 거부합니다. 과거 SQL이나 schema_migrations를 고치지 말고 DB schema와 일치하는 정식 image를 사용하세요. Migration은 최대 30분 동안 readiness를 보류하므로 배포 관리자의 startup 허용 시간도 이에 맞춥니다. rollback은 이전 앱이 새 schema를 읽을 수 있는지 확인한 경우에만 수행합니다.

11. 사설 CA와 TLS

내부 PostgreSQL, Keycloak 또는 AI endpoint가 사설 CA를 사용하면 기관의 전체 PEM CA bundle을 준비합니다. 추가 환경변수 없이 표준 trust bundle 경로를 교체합니다.

install -m 444 /secure/ca-certificates.crt \
  deploy/certs/ca-certificates.crt
docker compose --env-file .env \
  -f deploy/docker-compose.offline.yml \
  -f deploy/docker-compose.private-ca.yml \
  up -d --pull never
사설 루트만 넣으면 기존 공개 TLS가 실패할 수 있습니다. 운영에 필요한 공개 루트와 중간 인증서를 함께 포함하세요.

12. 관측과 실패 이벤트 복구

GET /metrics는 Prometheus text 형식으로 Flow·검색 지연, Flow 요청당 SQL 수, Outbox 지연·실패, DB pool과 WebSocket 연결 수를 제공합니다. endpoint는 reverse proxy에서 운영 수집망에만 허용합니다. 응답의 X-Request-ID는 JSON log의 request_id와 함께 장애 추적에 사용합니다.

알림 LISTEN consumer는 bounded channel 포화 시 backpressure를 적용합니다. 느린 browser socket은 연결을 종료해 최대 30초 backoff 재연결로 보내며, client는 연결 직후와 60초마다 REST unread summary를 다시 맞춥니다. 일시적인 WebSocket 재연결만으로 알림 row가 유실된 것으로 판단하지 마세요.

Dead Letter 재처리

  1. 감사 로그 → 실패 이벤트 복구에서 event type, 대상, 시도 횟수와 마지막 오류를 확인합니다.
  2. PostgreSQL, 권한이나 대상 데이터 같은 원인을 먼저 해결합니다.
  3. 재처리를 눌러 즉시 대기열로 되돌리고 Outbox 지연과 감사 기록을 확인합니다.
실패 이벤트 조회에는 audit:read, 상태를 바꾸는 재처리에는 별도 outbox:manage 권한이 필요합니다. 조사 역할과 복구 역할을 분리하고, 원인을 해결하지 않은 반복 재처리는 피하세요.

13. 실제 관리자 화면

v0.1.1 최종 릴리스 후보와 테스트 전용 데이터베이스로 관리자 route를 데스크톱·모바일에서 검증한 Playwright 실제 캡처를 제공합니다. 전체 62개 화면과 검증 결과는 manifest에 기록되어 있습니다.
