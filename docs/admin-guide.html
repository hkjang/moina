MOINA 관리자 가이드

외부 PostgreSQL 준비와 오프라인 이미지 반입부터 Keycloak, AI, 역할·권한, 선택형 승인과 신고·감사 운영까지 실무 순서로 정리했습니다.

버전 v0.1.0linux/amd64외부 PostgreSQLdistroless non-root

목차

배포 전 점검오프라인 설치최초 로그인일반 설정Keycloak OIDC역할·권한·키AI 설정승인 정책신고·제재백업·업그레이드사설 CA실제 화면장애 대응

1. 배포 전 점검

항목권장 조건
Container runtimeDocker 24+ 또는 호환 runtime, Compose v2
호스트linux/amd64, 시간 동기화, 최소 2 CPU·2 GiB RAM
PostgreSQL전용 database/user, UTF-8, TLS, 정기 backup, migration 권한
TLS기관 reverse proxy에서 HTTPS 종료, WebSocket/SSE 허용
선택 endpoint폐쇄망 내부 Keycloak과 AI API의 DNS·CA·방화벽 확인

GitHub Release에서 `moina-v0.1.0.tar.gz` 하나와 릴리스 본문의 SHA256을 별도 경로로 반입합니다. PostgreSQL 이미지는 포함되지 않습니다.

2. 오프라인 설치

파일과 이미지 확인

sha256sum moina-v0.1.0.tar.gz
gzip -t moina-v0.1.0.tar.gz
gzip -dc moina-v0.1.0.tar.gz | docker image load
docker image inspect moina:v0.1.0 \
  --format '{{.Os}}/{{.Architecture}} {{.Config.User}}'

결과는 `linux/amd64 nonroot:nonroot`여야 합니다.

3. 최초 관리자 로그인

  1. reverse proxy의 HTTPS 주소로 접속해 로그인 화면 버전을 확인합니다.
  2. bootstrap 아이디와 비밀번호로 로그인합니다.
  3. 개인 설정에서 bootstrap 비밀번호를 즉시 변경합니다.
  4. 별도 운영 관리자와 검토 역할을 만들고 최소 권한을 부여합니다.
  5. audit log에 최초 로그인, 비밀번호 변경과 사용자 생성 기록이 남았는지 확인합니다.

bootstrap 정보는 최초 계정을 보장하기 위한 값입니다. 이미 계정이 생성된 뒤 환경변수 비밀번호를 바꿔 기존 계정을 덮어쓰지 않습니다.

4. 일반 설정

서비스 관리자 → 일반 설정에서 서비스 이름, 기본 시간대, session 유지 시간, 사용자 가입, 개인 API key·MCP와 key별 요청 한도를 관리합니다. 업로드 설정 API에서는 파일 크기와 Moin당 미디어 수를 관리합니다. 환경변수는 추가하지 않습니다.

  • OIDC redirect URL은 Keycloak/OIDC 전용 설정에서 입력하거나 현재 요청 주소를 기준으로 자동 생성합니다.
  • 설정 변경과 수행자는 audit log에 기록하되 비밀값 원문은 남기지 않습니다.
  • 개인화 화면과 관리자 화면은 메뉴 그룹과 권한 경계를 분리합니다.
public base URL, 동시 session 수, Moin 길이, WebSocket·검색 정책은 v0.1.0 관리자 설정 항목이 아닙니다.

5. Keycloak OIDC

  1. Keycloak에 confidential client를 만들고 Authorization Code flow와 PKCE를 허용합니다.
  2. 관리 화면에 issuer URL, client ID, client secret과 redirect URL을 입력합니다.
  3. scope는 `openid profile email`부터 시작합니다.
  4. 기본 역할과 claim mapping, 자동 사용자 생성을 설정합니다.
  5. 연결 테스트에서 discovery, token endpoint와 redirect 일치를 확인한 뒤 활성화합니다.

client secret은 저장 후 다시 노출하지 않으며 설정 여부만 표시합니다. secret을 지울 때는 명시적인 삭제 동작을 사용합니다.

긴급 접근을 위해 최소 한 명의 로컬 최고 관리자 계정을 유지하고 강한 비밀번호와 접근 통제를 적용하세요.

6. 역할, 권한과 키

역할 이름과 permission 묶음은 관리자 화면에서 변경할 수 있습니다. 서버는 화면 숨김이 아니라 모든 API 요청에서 권한을 다시 검사합니다.

원칙적용
최소 권한읽기, 작성, moderation, 사용자, 설정, audit를 분리
개인 키소유자별 hash 저장, 원문 1회 표시, 만료와 최근 사용 기록
회전새 token 발급과 동시에 이전 token 무효화
MCP동일 permission 체계와 rate limit 적용, 관리 작업은 session 또는 별도 정책

역할 변경은 활성 session과 키의 유효 권한에 즉시 반영되어야 합니다. 정기적으로 장기 미사용 키와 만료 없는 키를 검토하세요.

7. AI 스트리밍 설정

내부 OpenAI-compatible endpoint의 base URL, API key, model, API style, timeout과 token 정책을 저장합니다. API key는 encryption key로 암호화하고 응답에 반환하지 않습니다.

  • streaming은 기본값이며 SSE 연결을 reverse proxy가 buffering하지 않도록 합니다.
  • output token 허용 범위는 1~262,144이지만 실제 model 상한 이하로 설정합니다.
  • URL은 HTTPS가 기본이며 폐쇄망 HTTP는 allowInsecureHttp를 명시한 경우에만 허용됩니다.
  • v0.1.0은 AI URL의 DNS/IP 재검증과 redirect 제한을 구현하지 않으므로 outbound 방화벽에서 신뢰된 내부 gateway만 허용합니다.

연결 테스트는 저장된 설정으로 /models 응답을 확인합니다. 사용자 입력과 응답 보존은 MOINA가 아닌 upstream gateway의 조직 정책도 함께 점검하세요.

8. 선택형 검토·승인 정책

승인 정책이 꺼져 있으면 제출·검토·승인·반려 단계와 승인 메뉴를 제외합니다. 켜면 지정 action에만 적용합니다.

  1. 정책을 켜고 검토 대상 action과 approver 역할을 선택합니다.
  2. 요청자가 Moin을 제출하면 암호화된 승인 snapshot을 저장하고 게시 전 대기 상태로 둡니다.
  3. 자기 승인을 금지하고 검토자가 승인하거나 사유를 포함해 반려합니다.
  4. 승인 대기 중인 Moin은 수정할 수 없으며, 내용을 바꾸려면 새 요청을 제출합니다.

승인·반려 event에는 actor, 시각, 대상, 결과와 검토 comment가 감사 log에 기록됩니다.

9. 신고와 제재 운영

v0.1.0 관리자 화면은 접수된 신고의 검토·해결·기각, 사용자 활성 상태와 게시물 삭제를 제공합니다. 신고 유형, 우선순위, SLA와 보존 기간을 사용자 정의하는 설정은 제공하지 않습니다.

  • 검토 메모에는 판단 근거를 남기고 필요한 moderation 권한만 부여합니다.
  • 사용자 비활성화와 게시물 삭제는 영향 범위를 확인한 뒤 수행합니다.
  • 기관별 보존 기간과 escalation 기준은 별도 운영 정책으로 관리합니다.
  • 반복 패턴을 관찰하되 자동 판단만으로 영구 제재하지 않습니다.

10. 백업과 업그레이드

백업

설정을 포함한 PostgreSQL 논리/물리 backup, 동일한 encryption key와 현재 image tar.gz를 서로 다른 보안 영역에 보관합니다. v0.1.0은 별도 설정 export나 online root-key rotation을 제공하지 않으므로 복구 훈련에서 DB backup과 원래 key가 함께 유효한지 확인합니다.

업그레이드

  1. 릴리스 notes와 migration을 검토하고 DB backup을 만듭니다.
  2. 새 tar.gz의 SHA256을 확인하고 이미지를 load합니다.
  3. staging에서 migration, 로그인, 주요 Flow와 rollback을 검증합니다.
  4. compose의 image tag를 바꾸고 재시작한 뒤 readyz와 버전을 확인합니다.

rollback은 이전 앱이 새 schema를 읽을 수 있는지 확인한 경우에만 수행합니다. destructive migration은 별도 변경 절차가 필요합니다.

11. 사설 CA와 TLS

내부 PostgreSQL, Keycloak 또는 AI endpoint가 사설 CA를 사용하면 기관의 전체 PEM CA bundle을 준비합니다. 추가 환경변수 없이 표준 trust bundle 경로를 교체합니다.

install -m 444 /secure/ca-certificates.crt \
  deploy/certs/ca-certificates.crt
docker compose --env-file .env \
  -f deploy/docker-compose.offline.yml \
  -f deploy/docker-compose.private-ca.yml \
  up -d --pull never
사설 루트만 넣으면 기존 공개 TLS가 실패할 수 있습니다. 운영에 필요한 공개 루트와 중간 인증서를 함께 포함하세요.

13. 장애 대응

증상우선 확인
readyz 실패PostgreSQL DNS/TLS/계정, migration 오류와 컨테이너 log
OIDC callback 실패issuer discovery, public URL, redirect URI, 시간 동기화, CA
SSE 중단reverse proxy buffering/timeout과 AI endpoint 연결
WebSocket 연결 실패Upgrade/Connection header 전달, idle timeout, origin 정책
복호화 오류올바른 encryption key가 주입됐는지 확인하고 임의 교체 중단

incident 기록에는 버전, image digest, 발생 시각, 화면의 오류 code, 관련 감사 event ID와 영향 범위를 포함하되 DSN, 비밀번호, token과 암호화 key는 포함하지 않습니다.
